# 42 — Archive fails on every row of the sidebar

> _This was generated by AI during triage._

**What to build:** archiving and unarchiving a conversation, and the panel that
lists the archived ones.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit — filed from the contract diff as M4,
then **seen happening** in the surface walk §S1. That changed its priority, not
its description.

## What happens

Not buried in a menu. Every thread row in the sidebar carries an
`Archive <title>` button. Pressing one puts **"Failed to archive thread"** on
screen:

```
--- pressed: Archive → Archive Okay, I'm using the laplus itself, here are few th..
  !! REFUSED: thread.archive
  !! ON SCREEN: Failed to archive thread
```

This is **the most reachable broken control in the application** — one press from
the default view, on every row.

`/settings/archived` is the other half, and renders _"Could not load archived
threads / Failed to load archived threads."_ — `orchestration.getArchivedShellSnapshot`,
refused.

## Key interfaces

- `thread.archive` and `thread.unarchive` — commands, currently unparsed. An
  archived flag on the thread row, published so the sidebar drops the row and the
  archived panel gains it.
- `orchestration.getArchivedShellSnapshot` — a method, currently missing.

## The one thing to settle while building

The snapshot method is the part with a question in it. Upstream is event-sourced
and can reconstruct a shell as it was; laplus keeps current state only
(ADR-0016), so "the shell snapshot for an archived thread" has to mean _the
thread's current row, filtered to archived_ rather than _the shell as it stood
when archiving happened_. Check the contract's declared response shape before
assuming the cheaper reading satisfies it — if the client only needs enough to
render a list and reopen a thread, the row is enough. If it wants history, say so
on this ticket and stop, because that is structural work and not this.

## Acceptance

- [ ] Pressing `Archive` on a sidebar row archives the thread. No error appears.
- [ ] The row leaves the sidebar and appears in `/settings/archived`.
- [ ] Unarchiving returns it to the sidebar with its transcript intact.
- [ ] `/settings/archived` on a profile with no archived threads renders an empty
      state, not an error.
- [ ] Archived state survives a restart.
- [ ] An archived thread's terminals and provider session are handled the same way
      the delete path handles them, or deliberately not — state which, and why, in
      the commit. Archiving is not deleting and probably should not stop a running
      session, but that should be a decision rather than an omission.
- [ ] Re-run `tools/ui-driver/surface-actions.mjs`; the `Archive` press reports no
      refusal.

## Out of scope

- Deleting a conversation — 49.
- Deleting checkpoint refs. Upstream leaks those on delete and does not touch them
  on archive; this ticket does not change that.
