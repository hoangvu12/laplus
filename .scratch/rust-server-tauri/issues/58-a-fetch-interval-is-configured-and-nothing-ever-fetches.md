# 58 — A fetch interval is configured and nothing ever fetches

> _This was generated by AI during triage._

**What to build:** either the fetch that `automaticGitFetchInterval` promises, or
an honest absence of the setting.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger R11.

## What happens

`automaticGitFetchInterval` is parsed, stored and published by `crate::settings`.
No code path anywhere runs `git fetch` — `crate::git` mentions fetch only in a
comment about which files churn.

So ahead/behind against the tracking ref only moves when something _outside_
laplus fetches. A developer watching the branch toolbar is watching a number that
updates when they happen to have run `git fetch` in a terminal.

This is consistent with `CONTEXT.md`'s standing position that the git status paths
cost no network — which is a real design property worth keeping. The problem is
that the setting claims otherwise.

## The two honest answers

1. **Implement it.** A periodic fetch on the configured interval, per project.
   The cost is real — network per project per interval, and `git fetch` on a large
   repository is not free — which is presumably why it was not done.
2. **Remove the claim.** If automatic fetching is not wanted, the setting should
   not be offered. `CONTEXT.md`'s position would then be complete rather than
   contradicted by a settings field.

Option 1 is the likelier answer because the setting is upstream's and removing it
is a divergence in a settings shape the client renders. But it should be a choice,
and the cost note below is the reason it is not automatic.

## What to be careful about if implementing

- A fetch is network I/O on a timer, per registered project. That scales with how
  many projects a developer has **registered**, not how many they use — the same
  trap ticket 38 declined a per-project `claude` probe over.
- A fetch that fails (no network, no remote, auth required) must not become a
  recurring error on screen.
- The existing coalesced live refresh (ticket 19) is the model for how not to make
  this thrash.

## Acceptance

- [ ] With the interval set, ahead/behind moves without the developer running
      `git fetch` themselves.
- [ ] With the interval unset or zero, nothing fetches.
- [ ] A project with no remote, or an unreachable one, does not produce repeated
      user-visible errors.
- [ ] Fetching does not block or delay the working-tree status path, which is on
      the interactive path and is deliberately network-free.
- [ ] Whichever answer is taken, `CONTEXT.md` and the setting agree with each
      other afterwards.

## Out of scope

- `vcs.pull` — 60. Fetching is not pulling.
- Any hosted source-control integration (spec exclusion).
