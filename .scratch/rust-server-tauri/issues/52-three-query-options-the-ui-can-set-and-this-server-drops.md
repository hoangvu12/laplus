# 52 — Three query options the UI can set and this server drops

> _This was generated by AI during triage._

**What to build:** `settingSources`, `additionalDirectories` and the provider's
`launchArgs` reaching the CLI invocation.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger R9.

## What happens

Upstream passes three query options that `crate::agent` does not:

- **`settingSources`** — which of the CLI's own settings files it should read.
  Without it, the CLI applies its full default set, which means a developer's
  user-scoped `settings.json` silently overrides what laplus asked for. That is
  the same divergence ticket 37 is about, seen from the other end.
- **`additionalDirectories`** — extra roots the agent may read outside the
  project. Relevant to any conversation that needs a sibling repository.
- **`extraArgs` from the provider's `launchArgs`** — **declared** as not ported in
  `crate::provider`. This one is the sharpest: `launchArgs` is a settings field
  **the UI can write**, and this server reads it and drops it. A developer sets it,
  sees it saved, and it does nothing.

## Key interfaces

- Wherever `crate::agent` assembles the child invocation.
- `launchArgs` is already parsed and stored by `crate::settings` — the gap is
  between storage and use, not at the wire.
- The declared note in `crate::provider` should be deleted, not amended, if this
  is built.

## What to be careful about

`launchArgs` is arbitrary developer-supplied arguments going onto a command line.
Decide and write down what happens when they conflict with an argument this server
sets itself (`--print`, `--output-format`, `--permission-prompt-tool` and the
rest). Appending blindly means a developer can break the protocol this server
depends on and get an unexplained failure. Refusing to append over a reserved flag,
and saying so, is the better answer — but it is a decision, so make it explicitly.

## Acceptance

- [ ] `settingSources` is passed, and a developer's user-scoped settings no longer
      silently override the mode laplus requested — or, if the CLI does not accept
      it in the form the binary exposes, that is recorded here and the item closed
      with a reason rather than left open.
- [ ] `additionalDirectories` is passed and the agent can read a directory added
      through it.
- [ ] `launchArgs` set in settings appear on the invocation.
- [ ] A `launchArgs` entry that collides with an argument this server owns is
      handled by a written rule, and the developer is told rather than left with a
      broken turn.
- [ ] Verified against the real binary. `claude --help` on the installed version
      is the authority for which of these the binary actually accepts — the SDK's
      option list is not.
