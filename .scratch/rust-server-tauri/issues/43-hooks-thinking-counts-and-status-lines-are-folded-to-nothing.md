# 43 — Hooks, thinking counts and status lines are folded to nothing

> _This was generated by AI during triage._

**What to build:** arms on `SystemEvent` for the four subtypes the CLI emits on an
ordinary turn and this server discards.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, measured against the real binary —
`.scratch/rust-server-tauri/2026-07-28-cli-stream-audit/` finding 3.

## What happens

`crate::protocol`'s `SystemEvent` has arms for `init` and `compact_boundary`.
Everything else falls to `SystemEvent::Other` and folds to `Nothing`. Measured
over two short turns against `claude` 2.1.220:

```
  25  system/thinking_tokens   → Other → Nothing
   3  system/status            → Other → Nothing
   2  system/hook_started      → Other → Nothing
   2  system/hook_response     → Other → Nothing
```

**Hooks fire on an ordinary turn.** A bare "reply with exactly: ok" emitted
`SessionStart:startup` with a full payload — `hook_name`, `hook_event`,
`exit_code`, `outcome`, `stdout`, `stderr`. A hook that _fails_ prints its reason
into a line this server folds to silence, so a developer whose hook is broken sees
a turn that behaves oddly and no statement of why.

`thinking_tokens` is a live thinking-token count. `status` says `"requesting"`,
and whatever else it says. Neither has a second source anywhere in the stream.

This is the same shape as the bug the compact-boundary test already records —
_"before this was recognised it fell to `SystemEvent::Other`, which is silence"_ —
still open, one subtype over. `crate::protocol`'s own doc comment names
`hook_started` and `hook_response` as subtypes it knows about and does not handle.

## Key interfaces

- `SystemEvent` — four new arms, each with the payload fields listed above.
- Where each one surfaces is the design work:
  - **hooks** want to be visible when they fail and quiet when they succeed. A
    failing hook is a developer-facing error; `SessionStart` succeeding on every
    turn is not a work-log row anyone wants.
  - **`thinking_tokens`** is a counter, not an event. It belongs wherever the
    thinking row already renders, as a number that moves — see 53, which is the
    other half of the same window.
  - **`status`** is transient. It may belong nowhere on screen and only in the
    log (57).

Decide each, and write the decision down. "Surfaced somewhere" is not the
acceptance criterion; "a broken hook is discoverable" is.

## Acceptance

- [ ] A hook that exits non-zero during a turn produces something the developer
      can see, carrying the hook's name and its stderr.
- [ ] A hook that succeeds does not add noise to every turn's work log.
- [ ] A fixture under `server/fixtures/claude-cli/` contains hook lines. None of
      the eighteen existing ones do.
- [ ] `thinking_tokens` and `status` are parsed into typed values rather than
      falling to `Other`, whether or not they reach the screen.
- [ ] The compact-boundary test's comment is no longer the only place this failure
      mode is recorded.

## Out of scope

- Whether an _unrecognised_ subtype should keep folding to silence. That is 44,
  and it is the more important half.
- Live thinking deltas — 53.
