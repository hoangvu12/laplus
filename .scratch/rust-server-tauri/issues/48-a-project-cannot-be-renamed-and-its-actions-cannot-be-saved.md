# 48 — A project cannot be renamed, and its actions cannot be saved

> _This was generated by AI during triage._

**What to build:** `project.meta.update`, which carries three things this server
currently refuses in one command.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit — ledger M8 from the contract diff, and
surface walk §S5, which found the second and more interesting half.

## What happens

`project.meta.update` is refused. Three consequences, in increasing order of
how surprising they are:

1. **A project cannot be renamed or recoloured.** Straightforward.
2. **A project's actions cannot be saved.** This is the one worth reading. The
   project actions menu opens with `Setup Worktree | Add action` — the repository's
   own `t3.json` script really does appear, because **the client reads `t3.json`
   itself** through `projects.readFile`, which laplus implements. So importing an
   action works right up until it is saved: the saved set is
   `OrchestrationProjectShell.scripts`, persisted through `project.meta.update`,
   and refused. The server's hardcoded `scripts: []` is therefore not merely
   unpopulated — it is **unpopulatable**.
3. The hook's own docstring describes `t3.json` scripts as offered "for import",
   which is a dead end one step further in than it looks.

## Key interfaces

- `project.meta.update` — carries at least `name`, a colour, and
  `scripts: Schema.optional(Schema.Array(ProjectScript))`. Read the full shape
  from the contract; the three above are what is known to be exercised.
- The projects table in `crate::store` needs somewhere to keep the scripts array.
  It is a list of small records, not free-form — `ProjectScript` is a declared
  contract type, so store it in that shape rather than inventing one.
- The published project snapshot must carry the saved scripts, replacing the
  hardcoded `[]`.

## Acceptance

- [ ] Renaming a project persists and appears in the sidebar.
- [ ] Recolouring a project persists.
- [ ] Importing `Setup Worktree` from `t3.json` and saving it keeps it across a
      restart, and it appears in the actions menu from the saved set rather than
      only from the file.
- [ ] A project with no `t3.json` can still have an action added by hand and kept.
- [ ] A `ProjectScript` field this server does not understand round-trips rather
      than being dropped, or is rejected loudly — not silently discarded.

## Out of scope

- Running `runOnWorktreeCreate`. Nothing runs it, and it needs worktrees (64)
  before it means anything.
- Actually _executing_ a project action — this ticket is about keeping one.
- `thread.meta.update`, which is a different command with a similar name and
  its own ticket (41).
