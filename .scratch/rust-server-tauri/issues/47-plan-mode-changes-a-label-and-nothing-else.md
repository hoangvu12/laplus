# 47 — Plan mode changes a label and nothing else

> _This was generated by AI during triage._

**What to build:** `interactionMode: "plan"` actually reaching the CLI.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger M2.

## What happens

The composer's interaction-mode picker offers plan mode. Selecting it stores
`interactionMode: "plan"` on the thread and echoes it back. Nothing else happens —
`crate::agent` maps only `runtimeMode` onto `--permission-mode`. The agent behaves
identically to before.

So the picker changes a label. A developer who selects plan mode and watches the
agent start editing files has been told something untrue by the UI.

## What upstream does

`ClaudeAdapter` calls `query.setPermissionMode("plan")` — the interaction mode is
a permission mode on the session, applied separately from the runtime mode.

laplus drives the binary rather than the SDK, so the question is which flag or
control message carries this. `--permission-mode` is the obvious candidate and
`crate::agent` already builds it from `runtimeMode`; the work is deciding how the
two compose when both are set, not finding the seam.

## Key interfaces

- Wherever `crate::agent` assembles the CLI invocation from a thread's modes.
- `interaction_mode` is already carried on the thread row and on `StartTurn`, so
  the value is in hand at the point the child is spawned.

## What to settle while building

**How `runtimeMode` and `interactionMode` compose.** They are two fields that both
want to be `--permission-mode`. Upstream keeps them separate because the SDK has
two seams; the binary has one. If plan mode wins over the runtime mode while it is
active, say so; if they are mutually exclusive in practice, say that instead. This
is a small decision but leaving it implicit will produce a confusing bug later.

## Acceptance

- [ ] Selecting plan mode and sending a turn produces an agent that plans rather
      than edits — verified against the real CLI, not only against a fixture.
- [ ] Leaving plan mode returns the agent to its previous behaviour without
      needing a new conversation.
- [ ] The composition of `runtimeMode` and `interactionMode` is written down where
      the next reader will find it.
- [ ] A conversation started in plan mode resumes in plan mode after a restart.
