# 60 — The pull button has no server behind it

> _This was generated by AI during triage._

**What to build:** `vcs.pull`.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger M13.

## What happens

The branch toolbar offers Pull. `vcs.pull` is unimplemented, so pressing it fails.

## Why this is small

The git surface this needs is already built and tested: working-tree status with
coalesced live refresh, branch list, switch, create, and `git init` all landed in
tickets 19–21. `crate::git` already shells out to `git` and already knows how to
report a working tree afterwards. Pull is one more subcommand into an existing
shape.

## What is not small

The failure cases, which are most of what a pull is:

- **Uncommitted changes** — a pull that would clobber them must refuse and say so,
  not fail with git's raw stderr.
- **No upstream tracking ref** — a common state, and the message should say what
  to do about it.
- **Merge conflict** — the working tree is now in a conflicted state and the UI
  needs to reflect that rather than reporting a generic failure.
- **Authentication** — a private remote over HTTPS or SSH may prompt. A prompt on
  a `git` child with no console is a hang. This is the one that will bite; decide
  how it is handled before writing the happy path.
- **No network.**

Each of these should produce a message a developer can act on. The existing binary
resolution diagnostic in `crate::provider` — which names what was looked for and
where — is the standard this repository already holds itself to for this kind of
error.

## Key interfaces

- `vcs.pull` — a method, currently missing. Read its declared response and error
  union from the contract; if refusing is still the right answer for some cases,
  refuse with a tag the union contains (see 39).
- `crate::git`'s existing status refresh, which must run after a successful pull
  so the toolbar and the file tree settle.

## Acceptance

- [ ] Pull on a clean tree with a tracking ref fast-forwards, and the toolbar's
      ahead/behind updates without a manual refresh.
- [ ] Each failure case above produces a specific, actionable message — not git's
      raw stderr and not a generic toast.
- [ ] A pull that would prompt for credentials fails with a message rather than
      hanging.
- [ ] A conflicted result leaves the UI showing a conflicted working tree.
- [ ] Pull is disabled or refuses honestly on a project that is not a git
      repository.

## Out of scope

- Push, and anything hosted — PRs, stacked diffs, clone, publish (spec exclusion).
- Automatic background fetching — 58.
- Conflict _resolution_ UI.
