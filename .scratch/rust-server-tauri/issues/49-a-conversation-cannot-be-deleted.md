# 49 — A conversation cannot be deleted

> _This was generated by AI during triage._

**What to build:** `thread.delete`, and the two cleanups that have to happen with
it.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger M3; the cleanup sequence read
from upstream in the decider audit §4.

## What happens

`thread.delete` is refused. The control is reachable from the chat view and from
the archived-threads panel; pressing it produces an error toast and the
conversation stays.

## The cleanup, which is the part with a specification

Upstream's deletion reactor is exactly two steps, **in order**:

1. `providerService.stopSession({ threadId })`
2. `terminalManager.close({ threadId, deleteHistory: true })`

Each is logged and **skipped on failure rather than aborting the other** — a
conversation whose agent process has already died still gets its terminals
closed. Follow that; the failure mode worth avoiding is a half-deleted thread
that cannot be deleted again because step one keeps throwing.

Note what upstream does **not** do: it does not delete the thread's checkpoint
refs. Those leak on both sides. That is not this ticket's problem to solve, and
"laplus should also delete them" is a change to behaviour upstream does not have —
if someone wants it, file it separately.

## Key interfaces

- `thread.delete` — a command, currently unparsed.
- `crate::threads` already owns session teardown for the interrupt and restart
  paths; the stop half should reuse it rather than growing a second way to end a
  session.
- Terminal close with history deletion — `crate::terminal` reaps terminals on
  window close today, so the per-thread close with `deleteHistory` may need adding.

## Acceptance

- [ ] Deleting a conversation removes it from the sidebar and it does not return
      after a restart.
- [ ] The agent process for that thread is stopped.
- [ ] The thread's terminals are closed and their scrollback removed.
- [ ] Deleting a thread whose agent has already exited still closes its terminals.
- [ ] Deleting a thread whose terminal close fails still leaves the thread deleted
      — the operation does not become un-retryable.
- [ ] Deleting the thread currently open navigates somewhere sensible rather than
      leaving a pane bound to a thread that no longer exists.
- [ ] Deleting an archived thread works from the archived panel too (see 42).

## Out of scope

- Checkpoint refs, per above.
- Undo. Neither server has it.
