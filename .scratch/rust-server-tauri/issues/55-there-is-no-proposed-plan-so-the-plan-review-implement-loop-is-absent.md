# 55 — There is no proposed plan, so the plan → review → implement loop is absent

> _This was generated by AI during triage._

**What to build:** capturing `ExitPlanMode`'s plan text as a proposed plan, so a
plan can be reviewed and then cited by a later turn.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger R3.

## What happens

`OrchestrationThread.proposedPlans` decodes to `[]` forever. laplus has no
proposed-plan path at all, so:

- when the agent calls `ExitPlanMode`, its plan text is not captured;
- the chat view's proposed-plan rows never appear;
- a later turn cannot cite `sourceProposedPlan`, because there is nothing to cite.

The whole plan → review → implement loop is missing. Ticket 47 — "the picker
changes a label" — is the smallest part of this, not the whole of it.

## What upstream does

`ClaudeAdapter` extracts the plan from the `ExitPlanMode` call
(`extractExitPlanModePlan`, keyed by `exitPlanCaptureKey`) and dispatches
`thread.proposed-plan.upsert`, which fills `OrchestrationThread.proposedPlans`.
A subsequent turn carries `sourceProposedPlan` referencing it.

## Key interfaces

- Tool recognition for `ExitPlanMode` in `crate::worklog`, alongside the Todo
  recognition from 54 — same seam, different tool.
- `thread.proposed-plan.upsert` — a command, and the thread state it writes.
- `OrchestrationThread.proposedPlans` on the published snapshot.
- `sourceProposedPlan` on turn start — the read side. A turn that cites a plan
  needs it to survive across turns, so this is thread state and not turn state.

## Ordering

This is worth building **after** 47. A proposed plan that can be captured but
never produced — because plan mode does not reach the CLI — is a feature with no
way to exercise it, and its acceptance criteria cannot be checked.

## Acceptance

- [ ] An agent in plan mode that calls `ExitPlanMode` produces a proposed plan on
      the thread.
- [ ] The plan text renders as a proposed-plan row in the conversation, not as a
      generic tool row.
- [ ] The proposed plan survives a restart.
- [ ] A later turn can be started citing that plan, and the citation reaches the
      agent rather than being dropped the way attachments are (63).
- [ ] A thread with no proposed plan still decodes and renders — `[]` remains
      valid.
- [ ] A second `ExitPlanMode` in the same thread upserts rather than duplicating.

## Out of scope

- The Todo-driven plan sidebar — 54. Different feature, similar vocabulary.
- Plan mode reaching the CLI — 47, and a prerequisite.
