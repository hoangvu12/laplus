# 62 — A checkpoint can be restored, but the agent cannot be rewound

> _This was generated by AI during triage._

because the obvious implementation is not available.

**Status:** needs-triage

**Found by:** the 2026-07-28 parity audit. Originally filed in the ledger as
"the infrastructure exists; this is the rewind" — **that was wrong**, and the
decider audit §3 (`.scratch/rust-server-tauri/2026-07-28-decider-audit.md`)
corrected it. Re-filed here as needing a decision rather than an implementation.

## What happens

`thread.checkpoint.revert` is refused. Restoring a checkpoint does nothing.

## Why it is not ready work

Upstream's revert is six steps:

1. refuse if `turnCount > currentTurnCount`, or the project is not a git repo;
2. `checkpointStore.restoreCheckpoint({ cwd, checkpointRef, fallbackToHead })`;
3. refresh the workspace entry index, so the `@`-mention picker matches the
   reverted tree;
4. **`providerService.rollbackConversation({ threadId, numTurns })`** — roll the
   _agent's own memory_ back by the same number of turns;
5. `deleteCheckpointRefs` for every checkpoint newer than the target;
6. dispatch `thread.revert.complete`.

laplus can do **1, 2, 3, 5 and 6 today** — it has the refs, the diff arithmetic
and the watcher. Step 4 is the problem, and it is a property of the transport
rather than of effort.

Upstream's `ClaudeAdapter.rollbackThread` truncates its in-memory turn list and
rewrites the resume cursor to `{ resume, resumeSessionAt, turnCount }`.
**`resumeSessionAt` is an Agent SDK option, not a CLI flag.** Verified against
`claude --help` on 2.1.220: the binary offers `--resume [sessionId]`,
`--session-id <uuid>` and `--fork-session`, and nothing that resumes _at_ a
message. Upstream can rewind because it drives the SDK; laplus drives the binary,
and the binary does not expose the seam.

Two further facts, both checked:

- **laplus discards the identifier this would need anyway.** `MessageEnvelope` is
  `{ message }` and nothing else, so the per-message `uuid` the CLI stamps on every
  assistant line is parsed and thrown away.
- **The CLI's own session store is a parent-linked chain.** Each line of
  `~/.claude/projects/<slug>/<sessionId>.jsonl` carries `uuid` and `parentUuid` —
  a real conversation tree, which is presumably what the SDK walks.

## The three options, none free

| Option                                                                                                                                         | What it costs                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Truncate the CLI's own JSONL** at the target assistant uuid before `--resume`, optionally with `--fork-session` to leave the original intact | Writing into another program's private store, with no compatibility promise. Mechanically sound — the chain is parent-linked — and the only route the binary leaves open. Needs `uuid` captured off assistant lines first. |
| **Restore files only**, and tell the agent nothing                                                                                             | Cheap and truthful about the filesystem. Leaves the agent believing it made changes that are gone — the exact state upstream added step 4 to avoid.                                                                        |
| **Restore files and start a fresh session**                                                                                                    | Correct in that the agent is never wrong; blunt in that the whole conversation's context goes with it.                                                                                                                     |

There is no fourth.

## What to do about it

1. **`/prototype`** the first option, because it is the only one whose feasibility
   is an open empirical question: _does truncating the session JSONL at an
   assistant `uuid` and then `--resume`-ing actually rewind the agent, or does the
   CLI reject, repair, or ignore the edit?_ Throwaway code; keep the answer.
2. **`/domain-modeling`** to record the outcome as an ADR. `server/docs/adr/` has
   sixteen; this is exactly the kind of decision they exist for, and whichever
   option is chosen it needs to be findable later by someone asking why revert
   behaves the way it does.
3. Then re-file the implementable half as `ready-for-agent`, with steps 1, 2, 3, 5
   and 6 specified and step 4 settled.

Capturing `uuid` off assistant lines is worth doing regardless — it is one field on
`MessageEnvelope`, it is needed by option 1, and it is currently thrown away.

## Acceptance

Deliberately not written. It depends on which option is chosen, and writing it now
would pick one by implication.

What can be said regardless:

- Reverting restores the working tree to the checkpoint.
- The `@`-mention picker matches the reverted tree afterwards.
- Checkpoints newer than the target are removed.
- Whatever happens to the agent's memory, the UI does not imply something
  different happened.
