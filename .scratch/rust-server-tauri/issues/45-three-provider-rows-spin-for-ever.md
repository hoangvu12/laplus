# 45 — Three provider rows spin for ever

> _This was generated by AI during triage._

**What to build:** a snapshot that says a provider is unavailable, so the three
drivers this build does not ship stop claiming to be loading.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, surface walk §S4.

## What happens

`/settings/providers` lists **Codex, Claude, Grok and OpenCode**. Claude reports
`v2.1.220 / Available`. The other three sit permanently on:

> Checking provider status — Waiting for the server to report installation and
> authentication details.

They will never resolve. laplus publishes exactly one provider instance and the UI
draws a row per built-in driver.

## Why this is not the scope decision showing through

"Claude Code only in v1" is settled (spec, Implementation Decisions) and is not
being reopened. But three rows implying the other drivers are _loading_ is not
that decision reaching the screen — it is the **absence** of the thing that would
state it. A developer reading that page learns that laplus is slow, not that it is
Claude-only.

Upstream has a module for precisely this case:
`provider/unavailableProviderSnapshot.ts` — _"when `providerInstances` references
a driver this build does not ship … produces shadow snapshots that satisfy
`ServerProvider`'s wire shape while signalling unavailability."_ Port the idea; it
is small and directly visible.

## Key interfaces

- Whatever `crate::provider` publishes as the provider snapshot list. It needs
  entries for the drivers this build does not ship, carrying an unavailable
  signal rather than being absent.
- Take the unavailable shape from the contract's `ServerProvider`, so the client's
  existing rendering path picks it up without a client change.

## Acceptance

- [ ] `/settings/providers` shows Codex, Grok and OpenCode as unavailable — a
      settled state, not a spinner.
- [ ] Claude's row is unchanged: `v2.1.220 / Available`, with the binary
      resolution diagnostic intact.
- [ ] Nothing on the page suggests the three will resolve later.
- [ ] Adding a second real driver later does not require deleting this — a driver
      that exists publishes a real snapshot and the shadow one is not emitted.
- [ ] Re-run `tools/ui-driver/surface-walk.mjs` against `/settings/providers`.

## Out of scope

- Implementing any other provider (spec exclusion — separate protocols, separate
  adapters).
- The wording on the row, which is upstream's.
