# 40 — The context meter is empty because six fields are undeclared

> _This was generated by AI during triage._

**What to build:** the composer's context-window meter, from data the CLI already
sends on every turn and this server already parses the line of.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, measured against the real binary —
`.scratch/rust-server-tauri/2026-07-28-cli-stream-audit/` finding 1.

## What happens

`ContextWindowMeter` reads the last activity of kind `context-window.updated`.
laplus emits none, so the meter never fills.

The reason is not that the data is unavailable. Every `result` line from
`claude` 2.1.220 carries, verbatim:

```json
"modelUsage": {
  "claude-haiku-4-5": {
    "inputTokens": 10, "outputTokens": 40,
    "cacheReadInputTokens": 0, "cacheCreationInputTokens": 27065,
    "costUSD": 0.05434,
    "contextWindow": 200000, "maxOutputTokens": 32000,
    "canonicalModel": "claude-haiku-4-5", "provider": "firstParty"
  }
},
"usage": { "input_tokens": 10, "cache_creation_input_tokens": 27065,
           "cache_read_input_tokens": 0, "output_tokens": 40, ... }
```

`ResultEvent` in `crate::protocol` declares `subtype`, `is_error`, `stop_reason`,
`num_turns`, `duration_ms`, `total_cost_usd`, `errors` and `result`. Serde drops
the rest silently. **So this is a struct definition, not a missing subsystem.**

The same shape arrives mid-turn on `message_delta.usage`, including
`output_tokens_details.thinking_tokens` — which is what makes the meter move
_during_ a turn rather than only at the end of one.

## What upstream does with it

`maxClaudeContextWindowFromModelUsage` takes `modelUsage` and returns the maximum
`contextWindow` across entries. `makeClaudeTokenUsageSnapshot` turns that and the
token counts into the snapshot that becomes a `context-window.updated` activity.
`apps/web/src/lib/contextWindow.ts` reads it. Follow that shape — the client is
already written against it.

## Also unread on the same line

Declare these while the struct is open, even if nothing consumes them yet:
`permission_denials`, `terminal_reason`, `api_error_status`, `fast_mode_state`,
`ttft_ms`, `duration_api_ms`, `usage.iterations`.

`terminal_reason` is worth a note: it is a **direct statement of how the turn
ended** (`"completed"`), where `crate::turn`'s `Ending` currently infers it.
Declaring the field is in scope here; changing `Ending` to prefer it is not.

## Key interfaces

- `ResultEvent` — six new fields, with the usage shapes as their own types.
- The `message_delta` arm — currently the usage payload is not read at all.
- A new activity of kind `context-window.updated`, whose payload must match what
  the client's `contextWindow` module decodes. Take the shape from the contract,
  not from this ticket.

## Acceptance

- [ ] After a turn completes, the composer's context meter shows a used/total
      figure derived from `modelUsage`, not zero.
- [ ] The meter moves mid-turn, from `message_delta.usage`.
- [ ] A fixture under `server/fixtures/claude-cli/` contains a `result` line with
      `usage` and `modelUsage`. **None of the existing eighteen do** — that is
      why this went unnoticed, so a fix without a new fixture has not been tested.
- [ ] Total is taken as the maximum `contextWindow` across `modelUsage` entries,
      matching upstream, rather than assuming a single entry.
- [ ] A turn whose `result` line carries no `modelUsage` (an older CLI) emits no
      activity and does not error.

## Out of scope

- Cost display. `costUSD` arrives here but where cost belongs on screen is a
