# 46 — Two subscriptions the client opens and this server does not answer

> _This was generated by AI during triage._

**What to build:** honest stubs for `subscribeAuthAccess` and
`subscribeServerLifecycle`, so connecting stops producing console errors.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger M18.

## What happens

The client opens both subscriptions on connect. This server answers neither, so
every boot logs errors and no auth-state or server-lifecycle information is
surfaced.

Neither has a feature behind it here. Accounts and auth are a spec exclusion —
permissive loopback handshake only, no login, no identity store, and
`auth.bootstrapMethods` is already honestly empty. Server lifecycle has more
substance but nothing currently drives it.

## What "honest" means here

Not "return success and go quiet". A stub should answer with the state that is
actually true — an auth-access stream that emits a single "no authorization is
required by this backend" state and then holds, rather than one that never emits
and leaves the client waiting.

The distinction matters because the failure mode this project keeps hitting is a
client that cannot tell "not yet" from "not ever" (see 45, and 39). Answering with
a settled state is the fix; answering at all is not.

## Key interfaces

- `subscribeAuthAccess`, `subscribeServerLifecycle` — take the emitted shapes
  from the contract.
- Note 39 is the same family of bug on the method side. If either of these has a
  declared error union, the same rule applies.

## Acceptance

- [ ] Connecting produces no console error from either subscription.
- [ ] Each emits a settled initial state rather than staying silent.
- [ ] The auth state emitted is consistent with `auth.bootstrapMethods` being
      empty — nothing implies a login is coming.
- [ ] Neither subscription leaks a task or handle when the client disconnects.

## Out of scope

- Accounts, login, identity, pairing (spec exclusion).
- Server self-update, which is a real lifecycle event but a separate item — 66.
