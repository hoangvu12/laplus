# 54 — The todo list never appears

> _This was generated by AI during triage._

**What to build:** `turn.plan.updated` activities, built from the Todo tool, so
the plan sidebar has something to draw.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger R2.

## What happens

The plan sidebar renders rows from activities of kind `turn.plan.updated`. laplus
emits none, so `TodoWrite` renders as a generic tool row and the sidebar is
permanently empty.

This is invisible to a contract diff, because laplus _does_ implement the methods
involved — it implements them answering with less.

## What upstream does

`ClaudeAdapter` recognises the Todo tool (`isTodoTool`), extracts the steps from
its input (`extractPlanStepsFromTodoInput`), and merges in subagent task state
(`planStepsFromClaudeTasks`) so a plan reflects work delegated to subagents as
well as work the main agent listed.

The merge is the part to notice. A plan built from `TodoWrite` alone is most of
the value; the subagent half depends on 56 and can follow it.

## Key interfaces

- Tool classification in `crate::worklog` — this is where the Todo tool has to be
  recognised as something other than a generic tool call. That module is already a
  port of upstream's `classifyToolItemType` / `titleForTool` /
  `summarizeToolRequest` and matches them, so it is the right seam.
- A new activity of kind `turn.plan.updated`. Take the payload shape from what
  the client's session logic decodes, not from this ticket.

## What to settle while building

**Whether the Todo row still appears in the work log once it also drives the
sidebar.** Upstream's answer is the authority here; a plan that appears in two
places at once is noise, and a `TodoWrite` that vanishes from the transcript
entirely is a hole. Check and follow.

## Acceptance

- [ ] A turn in which the agent calls `TodoWrite` fills the plan sidebar.
- [ ] Steps update as the agent revises the list within a turn, rather than only
      showing the first version.
- [ ] Step states (pending / in progress / done) render distinctly.
- [ ] A turn with no todo activity leaves the sidebar in an empty state, not an
      error.
- [ ] A fixture covering a `TodoWrite` turn exists.
- [ ] The plan survives a restart if the transcript does — or, if it deliberately
      does not, that is stated.

## Out of scope

- Subagent task state merged into plan steps — that depends on 56.
- Proposed plans from `ExitPlanMode`, which is a different feature with a
  confusingly similar name — 55.
