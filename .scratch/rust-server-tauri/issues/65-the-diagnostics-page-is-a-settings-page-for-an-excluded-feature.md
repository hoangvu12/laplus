# 65 — The diagnostics page is a settings page for an excluded feature

> _This was generated by AI during triage._

**What to build:** a decision about whether `settings.diagnostics` should exist at
all in v1.

**Status:** needs-triage

**Found by:** the 2026-07-28 parity audit, ledger M15 and surface walk §S2.

## What happens

`/settings/diagnostics` is backed by four unimplemented methods:
`server.getTraceDiagnostics`, `server.getProcessDiagnostics`,
`server.getProcessResourceHistory`, `server.signalProcess`.

Today the page shows a raw schema-decoder error. **Ticket 39 fixes that** and is
independent of this one — after 39 the page will show an honest empty state
instead. This ticket is about what, if anything, should be behind it.

## The tension

The spec names **"asset URL service, external diagnostics, process management"**
as out of scope for v1. So on the spec's own terms, these four methods are
correctly unimplemented and the answer here is `wontfix`.

But two things complicate that:

1. **The page exists.** The UI is upstream's and draws a diagnostics route
   whether or not this backend serves it. A permanently empty settings page is a
   better state than an error, and a worse state than an absent route.
2. **`signalProcess` is not diagnostics.** It is the ability to kill a runaway
   child. laplus spawns `claude` processes and terminal shells, and ticket 50 is
   about stopping a session cleanly. There is a real question about whether a
   developer needs a way to kill something that will not stop — and if so, that is
   not the excluded "external process management", it is this application managing
   its own children.

## The decision to take

- **If the exclusion holds in full:** close as `wontfix`, and consider whether the
  route should be hidden rather than shown empty. Write it to `.out-of-scope/` so
  the next parity audit does not re-file it — that directory does not exist yet
  and this would be its first entry.
- **If `signalProcess` is carved out:** re-file it as its own ticket against
  laplus's own children, and `wontfix` the other three.
- **If the whole page is wanted:** it is a real feature and needs a scope
  conversation, because the process and resource history methods imply sampling
  over time.

The middle option looks likeliest from here and is deliberately not chosen.

## Note on ordering

Do not wait for this to fix the error on screen. That is 39, it is a few lines,
and it applies whether or not any of these methods is ever built.

## Acceptance

Deliberately not written; it depends on the decision above.

What can be said regardless:

- No schema-decoder text reaches the page (39).
- Whatever the answer, the route does not imply a feature is loading when it is
  not — the same failure mode as 45.
