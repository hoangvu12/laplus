# 56 — A subagent is one collapsed row with no view inside it

> _This was generated by AI during triage._

**What to build:** the subagent task lifecycle, so a `Task` call shows what the
subagent is doing and what it cost.

**Status:** ready-for-agent

**Found by:** the 2026-07-28 parity audit, ledger R4.

## What happens

A `Task` call renders as one collapsed tool row labelled "Subagent task". There is
no view inside it: no progress, no per-task token usage, no indication of whether
it is running or finished.

**And the activity kind that would carry it is already taken.** `crate::turn`
reuses `task.progress` for **thinking** rows. Upstream's
`task.started` / `task.progress` / `task.completed` are the _subagent lifecycle_,
carrying per-task token usage.

So this ticket has a rename in it before it has a feature: the thinking rows need
to stop occupying the subagent kind, or the two need to be distinguished within
it. Do that first and deliberately — a partial fix that emits real subagent
progress onto the same kind thinking already uses will interleave two unrelated
things in one stream.

## What upstream does

`applyClaudeTaskToolResult` folds a task tool result into task state;
`normalizeClaudeTaskProgressTokenUsage` normalises the per-task usage that rides
along with progress. Task state also feeds the plan sidebar via
`planStepsFromClaudeTasks` — which is why 54 lists its subagent half as depending
on this ticket.

## Key interfaces

- `crate::turn`'s activity kinds — the collision above.
- `crate::worklog`'s handling of the `Task` tool.
- Per-task token usage, which shares shape with the usage work in 40. If 40 has
  landed, reuse its types rather than declaring a second set.

## Acceptance

- [ ] Thinking rows no longer use the subagent activity kind, and thinking still
      renders exactly as it does now.
- [ ] A `Task` call produces a started / progress / completed lifecycle.
- [ ] A running subagent is distinguishable from a finished one.
- [ ] Per-task token usage is reported.
- [ ] Several subagents running in one turn do not interleave into one another.
- [ ] A subagent that fails is visibly distinct from one that succeeded.
- [ ] A fixture covering a `Task` turn exists.

## Out of scope

- Merging task state into plan steps — that is 54's subagent half, and follows
  this.
- Nested subagents, if the CLI even produces them. Check; do not assume.
