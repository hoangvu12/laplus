# 06 — Treat the delegation tree as active work

**What to build:** Make parent-thread lifecycle and nested presentation account for the whole known delegation tree: descendants appear beneath their proven spawning child, keep the thread Working, and reach truthful terminal states when the developer stops the parent.

**Blocked by:** 02 — Show OpenCode's complete child work and blockers; 03 — Show Claude subagent work streams; 04 — Show Codex subagent work streams and hierarchy

**Status:** ready-for-agent

- [ ] When provider identity proves a child-to-child relationship, the nested child's compact launcher appears inside the spawning child's stream.
- [ ] Clicking a nested launcher opens or activates that descendant as another normal right-panel child tab.
- [ ] A descendant is not duplicated into the root transcript, and Laplus does not infer parentage the provider cannot prove.
- [ ] The thread remains Working while any known descendant is pending, running, or blocked, even when the root is quiet or its immediate turn has settled.
- [ ] The thread leaves Working only after the root and every known descendant reach terminal state.
- [ ] Stopping the parent stops the known active delegation tree under the initial shared Stop semantics.
- [ ] Every affected child stream records an interrupted terminal state and stops receiving ordinary live work after interruption.
- [ ] Closing any child tab remains presentation-only and cannot affect delegation-tree lifecycle.
- [ ] Child completion updates its compact row and lets parent orchestration continue without creating a toast or desktop notification.
- [ ] Cross-provider socket tests prove nested placement where supported, active-tree Working state, parent Stop, and truthful terminal settlement.
