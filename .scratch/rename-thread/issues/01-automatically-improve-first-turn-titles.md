# 01 — Automatically improve first-turn titles

**What to build:** After a developer starts a new conversation, Laplus replaces
the provisional first-message seed with a concise title generated by the
configured text-generation provider. The agent turn starts normally while title
generation runs in the background, every open client sees the resulting title,
and the title survives restart. If generation fails, the provisional title
remains and the conversation is unaffected. If the developer or provider changes
the title before generation completes, that newer title wins.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] A newly started conversation requests one generated title after its first user turn is accepted.
- [ ] Generation uses the configured text-generation provider independently of the conversation provider.
- [ ] Prompt dispatch, streaming, and settlement do not wait for title generation.
- [ ] A successful title reaches the thread feed and shell/sidebar feed, including another connected client.
- [ ] A fresh subscriber and a restarted server return the generated title.
- [ ] Failure or an unsupported generator leaves the provisional title intact and does not fail the turn.
- [ ] A manual rename or provider-native title update made while generation is pending cannot be overwritten by the late result.
- [ ] Resuming or replaying a historical conversation does not trigger first-turn generation again.
- [ ] Blank generated titles never replace a usable title.
- [ ] A real Claude conversation is driven in the window and its title visibly improves without manual editing.
