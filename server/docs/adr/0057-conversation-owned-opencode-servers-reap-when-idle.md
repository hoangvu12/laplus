# ADR-0057 — Conversation-owned OpenCode servers are reaped when idle

Date: 2026-08-22
Status: Accepted

A conversation-owned OpenCode server that has sat idle between turns — no turn in flight, nothing queued, nothing asked — is given up after ninety idle seconds, three times the shared text-generation pool's thirty (ADR-0043), because a conversation pays full serve startup and session adoption on return where a pooled request pays a socket dial. The decision is a pure function of idle time and session conditions (ADR-0043's pattern), and a reap ends the session quietly: no failure row, no retryable marker, no session event — the conversation reads exactly as it did after its last turn settled. Resumption is the durable cursor path as it already exists; the next prompt attaches a fresh server and adopts the session by id under ADR-0041's rules. An active turn refuses the reap at any age, and an unanswered permission or question holds the server past it, so an answer always reaches the agent that asked. External endpoints keep ADR-0036's guarantee in full: this machinery neither kills nor reaps them. Spawned owned servers receive opencode's own idle-instance disposal knob (`OPENCODE_IDLE_TIMEOUT`, thirty seconds) so their LSP and watcher instances shrink before laplus gives the process up — a knob evidenced upstream but absent from today's installed CLI, where setting it is inert.
